# Bible Study and Discover

Bible Study opens with the existing scrolling chapter/verse reader in the user's selected edition. Search and Ask AI are secondary entry points. Selecting a verse preserves the Simple, Deeper and Theology study levels; below each level, Discuss with AI opens an optional conversation and Open a public discussion hands the verse/theme to a Discover draft. Eight searchable themes remain available through search. Theme search is curated, not a semantic search over the entire Bible; a typed question can be carried into study AI. Resources link to STEP Bible for Hebrew/Greek and BibleProject for background and videos. External publishers retain their own language and theological perspective.

Discover now contains Discussions and Testimonies & stories. Discussions reuse the existing authenticated, moderated Community backend; creation is possible directly or from a study topic. Draft handoff stays in memory, never URLs, and requires preview then explicit publication. Edits invalidate the preview. The separate Community route continues to work. News is excluded server-side from all Discover filters and its scheduled refresh is paused; cached content is not deleted.

Study AI uses the existing Qwen secret server-side, authenticated with auth.getUser. It requires explicit consent, validates preferences, bounds request/history/response sizes, and shares the existing per-user journey rate limit. No study conversation is written to the database or attached to a community post. Conversation state resets on account/edition/language changes or leaving the study screen. Provider failures preserve the typed question. The model is instructed to distinguish interpretation from evidence, quote only supplied selected-edition passages, acknowledge uncertainty and avoid fabricated sources; general answers are not independently fact-checked or live-researched. The server's quotation grounding currently uses the existing curated edition passages, not a complete Bible retrieval index.

Validation: mobile typecheck, lint, unit suite, web export; PGlite regression covers exclusion and pagination across all/saved/stories while preserving stored news. Deployed endpoint rejects unauthenticated POST with 401. Live Discover query returns 12 non-news entries; cron job is absent. Authenticated Qwen response and moderated publication still require signed-in end-to-end confirmation. No test community posts were published.

Existing Supabase advisor findings remain outside this change (private default-deny tables, intentional authorized security-definer RPC entrypoints and password-protection configuration).
