# Journal action guide

The spreadsheet-derived `journal-map.json` is a versioned starting point, not a live connection to the spreadsheet. The model considers the full entry or latest chat alongside the map and returns one approved action. Keep both client and server map/selection copies synchronized. Edits to the spreadsheet require review and an explicit update here.

| Expressed need | Possible action | Considerations |
| --- | --- | --- |
| Wants company or a listener | Explore gatherings (A25), share in Confession (A04) | Never promise a listener or session; respect requests for privacy. |
| Wants to support someone by listening | Offer comfort (A14) | Opens the listener list, not a specific confession or an automatic reply. |
| Wants to bring people together | Create a gathering (A27) | Suggest when the person expresses readiness to host. |
| Wants to give back | Pay it forward (A18) | The person chooses from the page. Do not pressure donations, particularly with financial stress. |
| Remembrance or prayer with a candle | Candle (A01/A21) | Respect the person's candle preference. |
| Ongoing severe distress | Professional support (A05) | Do not diagnose or present a social gathering as treatment. Immediate danger uses the separate safety path. |

Actions are invitations. Do not force gratitude, public disclosure, or repeat previous suggestions. First responses and follow-up chat apply the same supported actions; an older client receives only actions it understands. The matching of an initial gathering suggestion uses only the selected theme locally, published public upcoming sessions, matching language, and explicit topic terms. It never sends journal text to the gathering catalog. The app checks before displaying a gathering action. If no relevant session is verified, it offers Confession only when the person expresses a wish to open up; otherwise the first response uses a private reflection and follow-up chat adds no action. A failed or timed-out lookup never asserts that there are no sessions. The action is checked again when opened because availability can change.

When AI guidance is enabled, the model is given the meaning of each supported action and asked for one brief reason grounded in the writer's words. The reason is retained only if it describes the same action that passes preference and safety checks. A later availability check can change or remove an action; if that happens, the original reason is discarded and an action-specific localized explanation is used instead. When guidance is off or a reason is missing or malformed, localized fallback copy explains the actual action. These checks do not guarantee that a model's wording is accurate or appropriate; evaluate representative real-provider responses before release.
